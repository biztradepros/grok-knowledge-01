# 클로드 × Make 리서치 팀 기획과 골격

> 상태는 draft 다. `approved` 는 사람만 붙이므로 이 폴더는 페이퍼 목록(index.json, insights.json)에 올리지 않았다.
> 숫자로 된 가격, 비용, 비밀 값은 일부러 적지 않았다. 연결 정보는 각자 Make 안에서만 넣는다.

---

## 1. 영상 내용 분석: 무엇을 가져올 것인가

영상의 요지는 한 줄이다. **AI가 내 일을 못 하는 이유는 능력이 아니라 맥락이 없어서다. 맥락은 파일로 준다.**

| 영상의 개념 | 뜻 | 리서치 팀에 옮기면 |
|---|---|---|
| 전역 CLAUDE.md | 나에 대한 공통 정보. 모든 대화에 깔린다 | **회사 프로필**: 우리가 누구고, 누구에게 무엇을 파는지 |
| 프로젝트 CLAUDE.md | 폴더(업무)별 규칙 | **팀별 업무 지침**: 리서치 팀이 어떤 출처를 보고, 어떤 형식으로 남기는지 |
| "정보 폴더에 날짜 붙여 저장" | 시키지 않아도 지켜지는 습관 | **산출물 규칙**: `YYYY-MM-DD_주제.md`, 출처 필수 |
| 업무별 폴더 분리 (마케팅·법무·HR…) | 하나의 AI를 여러 직무로 나눔 | **팀원 분리**: 수집가·분석가·검증가·작성가 |
| 파일 고치면 새 대화 | 맥락은 시작할 때 한 번 읽힌다 | Make에서도 **프롬프트는 실행 때마다 시트에서 새로 읽게** 한다 |

영상이 다루지 않은 빈칸이 두 개 있다. 이 기획은 그 빈칸을 채운다.

1. **사람이 시켜야만 움직인다.** 클로드 코드는 내가 창을 열어야 일한다. 매일 아침 공고를 훑는 일은 사람이 잊는다.
2. **혼자만 쓴다.** 결과가 내 PC 폴더에 남는다. 고객에게 보내거나 팀이 같이 보려면 다른 통로가 필요하다.

→ 그래서 역할을 나눈다.

- **클로드 코드 = 두뇌와 작업실.** 깊게 파고드는 리서치, 지침과 프롬프트 설계, 결과 검토.
- **Make = 신경망과 손발.** 정해진 시간에 깨어나서 수집하고, Claude에게 넘기고, 시트·메일·슬랙으로 보낸다.

## 2. 둘을 잇는 구조

```
                ┌──────────────── 사람 (대표) ────────────────┐
                │  승인 / 고객 응대 / 지침 수정                 │
                └───────▲──────────────────────────┬──────────┘
                        │ 리포트·알림                │ 지침 수정
┌───────────────────────┴─────────┐     ┌──────────▼─────────────────────┐
│ Make (자동, 매일·매주)            │     │ 클로드 코드 (수동, 깊게)          │
│ 트리거 → 수집 → 필터 → Claude API │     │ 전역 CLAUDE.md = 회사 프로필      │
│ → JSON 파싱 → 시트 → 메일/슬랙    │     │ research-team/CLAUDE.md = 팀 규칙 │
└───────────────┬─────────────────┘     │ .claude/agents = 팀원 4명         │
                │                       └──────────┬─────────────────────┘
                ▼                                  ▼
        ┌──────────────── 공용 저장소: Google Sheets + Drive ─────────────┐
        │ profile(회사 프로필) · clients(고객 프로필) · sources(출처 목록)  │
        │ items(수집·채점 결과) · reports(발행 기록)                        │
        └────────────────────────────────────────────────────────────────┘
```

핵심 설계 원칙 세 가지.

1. **영상의 '전역 CLAUDE.md'를 Make에서는 `profile` 시트로 만든다.** 모든 시나리오가 첫 단계에서 이 시트를 읽어 Claude의 system 프롬프트 앞에 붙인다. 프로필을 고치면 다음 실행부터 바로 반영된다. (영상의 "고친 뒤 새 대화" 규칙이 자동으로 지켜진다.)
2. **Claude는 항상 JSON으로 답하게 한다.** Make는 자유 문장을 다루기 어렵다. `make/prompts/` 의 프롬프트는 모두 정해진 JSON 스키마로만 답하게 짜여 있다.
3. **싼 모델로 거르고, 좋은 모델로 쓴다.** 건마다 돌리는 분류·채점은 Haiku 4.5(`claude-haiku-4-5-20251001`), 고객용 리포트 작성은 Sonnet 5.5(`claude-sonnet-5-5`), 주간 종합 분석만 Opus 5.5(`claude-opus-5-5`). Make 작업 수와 토큰을 함께 아낀다.

## 3. 수익이 나는 리서치 팀 아이디어

평가 기준: **돈을 내는 사람이 분명한가 / 매번 반복되는가(자동화 가치) / 공개 출처로 되는가(법적 위험) / 하루 만에 첫 버전이 되는가.**

| # | 아이디어 | 누가 돈을 내나 | 반복성 | 자동화 적합도 | 위험 | 종합 |
|---|---|---|---|---|---|---|
| A | **정부지원사업·입찰 공고 레이더** | 중소기업, 스타트업, 컨설팅사 | 매일 새 공고 | ★★★★★ RSS·목록 페이지가 정형적 | 낮음 (공개 공고) | **1순위** |
| B | **해외 바이어·수출 시장 리서치** | 수출 준비 제조사, 무역 대행 | 고객별·국가별 반복 | ★★★★ 리드 목록 → 건별 조사 | 중간 (개인정보 주의) | **2순위** |
| C | **경쟁사·가격·리뷰 모니터링 주간 리포트** | 쇼핑몰, 브랜드, 마케팅 대행사 | 매주 | ★★★★ 지정 URL·RSS 감시 | 중간 (약관상 수집 제한 확인) | 3순위 |
| D | 유튜브·트렌드 콘텐츠 기획 리서치 | 크리에이터, 1인 기업 | 매주 | ★★★ | 낮음 | 부가 상품 |
| E | 법령·규제 변경 알림 (업종별) | 인허가 업종, 수출입 | 수시 | ★★★ 원문 해석은 사람 검토 필수 | 높음 (오해석 책임) | 보류 |

**왜 A가 1순위인가.** 공고는 매일 쏟아지는데 "우리 회사에 맞는 것"을 고르는 일은 지루하고, 놓치면 손해가 분명하다. 고객 프로필(업종·지역·업력·매출 규모)을 한 번 받아 두면 이후는 전부 자동이다. 영상의 "나에 대해 아는 AI"를 **"고객에 대해 아는 AI"** 로 바꾼 것이 곧 상품이다.

**왜 B가 2순위인가.** 저장소 이름(biztradepros)으로 보아 무역 쪽 경험이 있다면 차별점이 생긴다(추정이다. 아니라면 C를 2순위로 올린다). 바이어 후보 목록을 넣으면 회사 개요, 수입 품목 추정, 접촉 포인트, 첫 메일 초안까지 한 행씩 채워진다.

**과금 방식(숫자는 시장 확인 후 결정).**
- A: 월 구독. 고객 프로필 1개 = 1구독. 상위 등급은 "신청서 초안 작성"을 사람 검토와 묶어 건별 추가.
- B: 건별(바이어 N곳 조사 패키지) + 월 갱신.
- C: 월 구독, 감시 대상 수에 따라 등급.

**팀이 강해지는 지점 = 쌓이는 데이터.** 모든 수집·채점 결과가 `items` 시트에 쌓인다. 석 달이면 "이 업종은 어떤 공고에 자주 붙는가"가 보이고, 그게 다음 상품(전략 리포트, 컨설팅)의 원료가 된다.

## 4. Make로 자동화할 만한가: 분석

| 작업 | Make 적합? | 이유 |
|---|---|---|
| 정해진 시간에 RSS·목록 수집 | ✅ 매우 적합 | Schedule + RSS / HTTP 모듈이 기본 기능 |
| 중복 제거, 키워드 1차 필터 | ✅ 적합 | Data store 조회 + Filter. 여기서 걸러야 Claude 호출 수가 준다 |
| 고객 프로필과의 적합도 채점 | ✅ 적합 | Claude(Haiku) 1회 호출 + JSON 파싱 |
| 고객별 다이제스트 메일 발송 | ✅ 적합 | Iterator → Text aggregator → Gmail/Outlook |
| 깊은 시장 분석, 신청서 초안 | ⚠️ 부분 | 긴 문서는 Make 타임아웃·토큰 한도에 걸리기 쉽다. 초안까지만 자동, 완성은 클로드 코드에서 사람이 |
| 로그인 필요한 사이트, 자바스크립트로 그리는 페이지 긁기 | ❌ 부적합 | 깨지기 쉽고 약관 문제. 공식 RSS·API·공개 목록만 쓴다 |
| 사실 확인(숫자·날짜) | ⚠️ 부분 | Claude가 원문 대조 체크는 하되, 마감일·자격 요건은 원문 링크를 반드시 같이 보낸다 |

결론: **"수집 → 거르기 → 채점 → 배달"은 Make, "깊이·판단·최종 책임"은 클로드 코드와 사람.** 이 경계를 지키면 자동화 효과는 크고 사고는 작다.

## 6. 실행 순서 (로드맵)

**1일차 — 맥락 깔기 (영상 그대로)**
1. `claude/global-CLAUDE.md` 를 채워 전역 위치(`~/.claude/CLAUDE.md`, 윈도우는 `C:\Users\사용자명\.claude\CLAUDE.md`)에 둔다. 클로드에게 "전역 CLAUDE.md에 이 내용 넣어 줘"라고 시켜도 된다.
2. `claude/research-team/` 폴더를 통째로 내 PC에 복사하고 그 폴더에서 클로드 코드를 연다.
3. 새 대화에서 "이번 주 우리 회사에 맞는 정부지원사업 찾아 줘"로 시험한다. `정보/` 폴더에 날짜 붙은 파일이 생기면 성공.

**2~3일차 — 공용 저장소**
4. Google Sheets 하나에 `make/sheets/*.csv` 헤더로 탭 6개를 만든다.
5. `profile` 탭에 전역 CLAUDE.md와 같은 내용을 넣는다. (진실은 하나: 바뀌면 둘 다 고친다. 귀찮으면 클로드 코드에 "프로필 시트 내용과 전역 CLAUDE.md를 맞춰 줘"라고 시킨다.)

**4~7일차 — Make 첫 시나리오**
6. S1을 만든다. 처음엔 출처 2개, 고객 1명(나 자신)으로만.
7. 일주일 돌려 `items` 탭의 점수와 내 판단을 비교하고 `make/prompts/score-item.md` 를 고친다.

**2~4주차 — 상품화**
8. 지인 고객 3명을 무료로 붙여 S2 다이제스트를 보낸다. 반응이 좋은 형식을 고정.
9. S3, S4 추가. 유료 전환.

## 7. 지켜야 할 선

- 공개 출처만 쓴다. 사이트 약관과 robots 규칙을 확인한다.
- 고객 프로필에 주민번호·계좌 같은 개인 식별 정보는 받지 않는다.
- 마감일·자격 요건은 AI 요약만 보내지 않는다. **원문 링크를 반드시 같이** 보낸다.
- 법률·세무 판단은 "검토 필요" 표시까지만. 결론은 전문가가 낸다.
- 연결 정보(Anthropic 연결, Google 연결)는 Make의 Connections에만 둔다. 이 저장소나 시트에 적지 않는다.

## 8. 이 폴더의 파일

```
drafts/make-research-team/
├── README.md                         ← 이 기획서
├── claude/
│   ├── global-CLAUDE.md              ← 전역 지침 템플릿 (회사 프로필)
│   └── research-team/
│       ├── CLAUDE.md                 ← 리서치 팀 프로젝트 지침 (팀장 역할)
│       └── .claude/agents/
│           ├── scout.md
│           ├── analyst.md
│           ├── fact-checker.md
│           └── writer.md
└── make/
    ├── scenarios/                    ← 시나리오 설계서 (모듈 순서·매핑)
    │   ├── S1-grant-radar.md
    │   ├── S2-client-digest.md
    │   ├── S3-lead-research.md
    │   └── S4-weekly-insight.md
    ├── prompts/                      ← Make의 Claude 모듈에 붙여 넣을 프롬프트
    │   ├── score-item.md
    │   ├── lead-research.md
    │   └── weekly-insight.md
    ├── schemas/
    │   └── score-item.schema.json    ← Claude 응답 JSON 구조 (Parse JSON용)
    └── sheets/                       ← Google Sheets 탭 헤더
        ├── profile.csv
        ├── clients.csv
        ├── sources.csv
        ├── items.csv
        ├── leads.csv
        └── reports.csv
```

Make 시나리오는 Make 화면에서 직접 조립하도록 **모듈 순서와 매핑을 문서로** 적었다. Make 블루프린트 JSON은 모듈 버전과 연결 ID가 계정마다 달라 그대로 가져오면 깨지기 쉽기 때문이다. 한 번 손으로 만든 뒤 Make에서 Export Blueprint 해서 이 폴더에 넣어 두면 그때부터는 복제가 쉽다.
